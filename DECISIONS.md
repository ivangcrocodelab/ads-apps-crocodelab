# Решения

## Область реализации

Реализованы F1–F7 на уровне кода и локальных проверок. Полная проверка на
нескольких реальных магазинах ещё не проведена. Релизные работы приостановлены
по указанию владельца; hosting, review и видео сейчас не готовятся.

- Основа: официальный Shopify React Router template, исходный commit
  `81eb98b6ca095eb0b92657f6007939a418f61955`.
- TypeScript, Node.js 22, App Bridge, Polaris web components.
- React обновлён с 18 до 19 вместе с типами: корректная передача свойств
  и событий custom elements, используемых Polaris в формах.
- PostgreSQL и Prisma. SQLite из шаблона заменён до первого развёртывания.
- Один сервер, без Redis и микросервисов.
- GraphQL Admin API и webhooks: `2026-10`, как в шаблоне.
- Scopes: `read_products` и `write_app_proxy`. App Proxy используется
  для выдачи карточек и подписанного перехода с витрины.
- Автоматический допуск: предварительное одобрение оператора не требуется.
  Блокировка сохраняется при переустановке. Роли и каталог выключены по умолчанию.
- Ниша из десяти значений ТЗ; до выбора хранится NULL, без придуманного значения.
- Профиль создаётся в afterAuth из проверенной Shopify-сессии и GraphQL Shop.
  Идентификатор магазина из формы не принимается.
- Только offline-сессии; имена/email сотрудников не запрашиваются.
- Бонус: 20 целых кредитов, ключ `welcome:<Shopify Shop GID>`. SQL INSERT ON CONFLICT магазина
  блокирует строку; журнал и баланс изменяются в одной транзакции.
- Удаление приложения отключает роли и каталог, удаляет сессии.
  Shop/redact удаляет данные магазина, сохраняя только HMAC Shopify ID
  и факт выдачи бонуса — выбранный владельцем компромисс. Для HMAC нужен
  постоянный отдельный BONUS_RETENTION_SECRET; основание хранения
  согласуется до публикации.

## Решения до production

Compliance webhooks реализованы; payload с данными покупателей не сохраняется.
Юридические основания хранения минимального признака бонуса не предполагаются автоматически.
Хостинг и платные ресурсы пока не выбраны и не подключены.
Для production потребуются HTTPS, безопасное хранение секретов, бэкапы,
проверенное восстановление и полная живая приёмка. Эти работы сейчас отложены.

## Партнёры, товары и клики

- A→B и B→A — разные записи; нужны оба согласия и обе категории.
  Каталог только по согласию; приглашение действует 7 дней, в БД хранится хеш.
- Выбор не более 10 товаров, с подтверждением прав. Поля цены не запрашиваются.
  Перед выдачей карточки и обработкой клика актуальность проверяется через API.
  Ошибка исключает товар. Порог свежести для транзакционной проверки — 30 секунд.
- Варианты товара проверяются страницами по 100 до первого доступного варианта
  или конца списка. Ошибка любой страницы исключает товар из выдачи.
- Токен содержит случайный nonce, срок и HMAC; TTL 5 минут. БД связывает его
  с товаром, направлением и версиями настроек обеих сторон. Одно погашение.
- Лимиты на площадку: 120 загрузок и 30 кликов в минуту. IP, cookies и
  постоянные идентификаторы посетителей не используются. Это простая защита,
  не доказательство человеческого клика и не сложная антифрод-модель.
- Блок учитывает marketing/analytics consent через Customer Privacy API.
  Без согласия и при ошибке скрыт. Карточки создаются через безопасные DOM API.
- Оператор использует HTTP Basic с отдельным длинным паролем и CSRF с проверкой
  Origin. Промокредиты требуют причины и уникального ключа операции.
- Очередь и Redis не добавлены. Maintenance — отдельная команда; синхронная
  проверка актуальности не зависит от её расписания. Логи не содержат payload,
  токены, адреса покупателей или полные объекты ошибок.

## Проверка зависимостей

При реализации шага 1 `npm audit --omit=dev` сообщил 6 записей:
4 high по цепочке Prisma/config/deepmerge-ts и 2 moderate по
fs-routes/minimatch. Первичные проблемы: рекурсивное слияние объектов
deepmerge-ts <8 и сложные glob-шаблоны minimatch <11.0.1.
Это инструменты конфигурации/сборки; пользовательские объекты и glob-выражения
в них приложение не передаёт. Это не означает полного отсутствия риска.
Предлагаемые npm исправления меняют major-версии Prisma/адаптера; автоматический
audit fix --force не применён. До production нужно обновить совместимую связку
и повторить проверки. Lockfile сохраняется для воспроизводимости.

## Локальная проверка

Для тестов подготовлена PostgreSQL 18.6 из официальных бинарников EDB,
в `.cache/postgres`, без системной службы; слушает только 127.0.0.1:55432,
аутентификация SCRAM-SHA-256. Секреты и данные исключены из Git и Docker.
Конкурентный тест выявил гонку эмулированного Prisma upsert при двух уникальных
полях. Он заменён параметризованным SQL INSERT ON CONFLICT с блокировкой строки.
Проверены также HMAC webhook и отклонение поддельных Shopify session tokens.
