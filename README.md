# Партнёрская реклама Shopify

Реализованы кабинет с независимыми ролями, направленные разрешения партнёров,
каталог и приглашения, выбор до 10 товаров, рекламный app block, учёт кликов
и кредитов, статистика, панель оператора и compliance webhooks.
Платежей, заказов, пикселей и профилей покупателей нет.

Релизные работы остановлены по указанию владельца. Полная приёмка на нескольких
реальных магазинах и визуальная проверка кабинета пока не выполнены.

## Локальный запуск

Для одновременной проверки на двух dev stores нужны два работающих `shopify app dev`:
dev URL обновляется только для выбранного магазина. Остановленный туннель другого
магазина приводит к HTTP 500 на `/apps/partner-ads/ads`.

Первый процесс запускайте обычным способом. Во втором PowerShell используйте:

```powershell
$env:SHOPIFY_REUSE_PRISMA_CLIENT = '1'
npm.cmd run dev -- --store test-shop-with-checkout-ext.myshopify.com --theme-app-extension-port 9495
```

Укажите другой магазин, чем в первом процессе, и свободный порт расширения.
Пароль витрины вводите по запросу CLI. Режим повторного использования проверяет
схему и версию Prisma Client и не перезаписывает DLL, занятую первым сервером.
После изменения схемы или версии Prisma остановите оба процесса и выполните
`npm.cmd run setup` перед новым запуском. Оба dev-процесса должны оставаться запущенными.

Нужны Node.js >=22.12, npm, Shopify CLI, PostgreSQL и тестовый магазин Shopify.
В Windows PowerShell при запрете запуска `npm.ps1` использовать `npm.cmd`
вместо `npm` в командах ниже; менять системную ExecutionPolicy не требуется.

1. `npm ci`
2. Скопировать `.env.example` в `.env`, указать `DATABASE_URL`.
   Задать независимые случайные `CLICK_TOKEN_SECRET`, `BONUS_RETENTION_SECRET`
   и `OPERATOR_PASSWORD` длиной не менее 32 символов, а также `OPERATOR_USER`.
   Секреты не коммитить. Секрет бонуса должен сохраняться между переустановками.
3. `npm run setup` — генерация Prisma и применение миграций.
4. При подключении другого приложения выполнить `npm run config:link`.
   Текущий TOML уже связан с приложением владельца; scopes:
   `read_products,write_app_proxy`.
5. `npm run dev -- --store cro-theme-development.myshopify.com`.
   Открыть ссылку кабинета, которую выдаст CLI.

CLI передаёт Shopify API key, secret и URL в процесс разработки. Для отдельного
процесса нужны `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SHOPIFY_APP_URL` и
`SCOPES` из окружения. Не запускать генерацию Prisma параллельно серверу на Windows:
используемая сервером DLL может быть заблокирована.

В кабинете доступны Home, My products, Partners, Display partners, Balance.
Для рекламы выбрать нишу, включить роль, товары и площадки; площадка должна
разрешить рекламодателя и его категорию. Обратное направление автоматическиу
не включается. Площадка вручную добавляет Partner ads в Theme Editor.
Блок требует согласия marketing и analytics через Customer Privacy API;
без согласия, подходящих товаров или при ошибке остаётся скрытым.

Для установки со страницы приглашения задайте `SHOPIFY_APP_STORE_URL` — HTTPS-ссылку
на листинг приложения на `apps.shopify.com`. Магазин выбирается средствами Shopify;
ручного ввода домена нет. Пока ссылка не задана, приглашение показывает код подключения
для уже установивших приложение, но не предлагает новую установку.

Панель `/operator` защищена HTTP Basic и CSRF. Она позволяет блокировать магазины,
скрывать объявления и начислять промокредиты с обязательной причиной.

## Проверки

```powershell
npm run typecheck
npm run lint
npm run build
npm run test:storefront
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/local-db.ps1 Test
```

Последняя команда использует подготовленную portable PostgreSQL в `.cache/postgres`
на `127.0.0.1:55432`, отдельную БД `partner_ads_test` и игнорируемый файл соединения.
При необходимости сначала выполнить тот же скрипт с `Start`.
На другом компьютере применить миграции к отдельной тестовой БД, задать
`TEST_DATABASE_URL` и выполнить `npm run test:db`. Без этой переменной тесты
не запускаются. Они создают и удаляют только свои записи.

Интеграционные тесты проверяют настоящие транзакции PostgreSQL, конкуренцию
последнего кредита и повторов, взаимные разрешения, лимит товаров, отзыв доступа,
модерацию, бонус и переустановку, удаление, HMAC/сессии и защиту оператора.
Shopify-ответы в этих тестах подменены. Отдельно успешно выполнены реальные
read-only GraphQL-запросы списка и актуальности товаров в предоставленном магазине.
Тесты storefront проверяют скрытие блока, согласие, безопасный вывод карточек
и отклонение синтетического клика. Они не заменяют визуальную проверку браузером.

## Обслуживание локального кода

После сборки `npm run maintenance` обновляет выбранные товары и удаляет истёкшие
токены, приглашения, лимиты и webhook receipts старше 30 дней. Команда требует
полного окружения Shopify; переменные dev-процесса CLI не передаются ей автоматически.
Перед показом и кликом товары также проверяются синхронно; ошибка проверки
исключает объявление, даже если maintenance не запускался.

Архитектура и компромиссы: [DECISIONS.md](DECISIONS.md).
Модели и транзакции: [DB_SCHEMA.md](DB_SCHEMA.md).
Production, проверка Docker/восстановления, материалы review и видео отложены;
наличие Dockerfile не означает проверенное развёртывание.
