# Схема БД

PostgreSQL, Prisma; миграции `202611120001_initial` и `202611130001_mvp`.

| Таблица | Назначение и ключи |
| --- | --- |
| Session | Offline-сессии Shopify, ключ id |
| Shop | Shopify GID, уникальный domain, ниша, независимые роли, каталог, блокировка, даты, settingsVersion |
| CreditAccount | Один счёт на магазин; целочисленный баланс >= 0 |
| CreditOperation | Вид операции, причина, уникальный idempotencyKey |
| CreditEntry | Ненулевая проводка; уникальная пара operationId/shopId |
| ShopCategoryPreference | Составной ключ shopId/role/niche |
| Partnership | Уникальная направленная пара advertiserId/publisherId, два согласия и блокировки, версия |
| PartnerInvitation | Хеш случайного токена, магазин и срок действия |
| ProductAd | Уникальная пара shopId/productId; поля карточки, права, выбор, актуальность, модерация, revision |
| BlockLoad | Загрузка блока площадки; не гарантированный просмотр |
| ClickToken | Уникальный nonce, участники, товар, версии разрешений и настроек, срок и погашение |
| CountedClick | Учтённое событие по nonce; nullable идентификаторы участников для удаления данных |
| RateLimit | Хеш ключа магазина и временного интервала, счётчик, срок |
| WebhookReceipt | Уникальный id события Shopify, тема, дата |
| BonusReceipt | Только HMAC Shopify ID и факт выдачи стартового бонуса |
| OperatorAudit | Действие оператора, магазин, причина, дата |

Shop связан с настройками, разрешениями, товарами и счётом. CreditOperation
содержит проводки по счетам. CHECK-ограничения запрещают отрицательные балансы,
нулевые проводки, направление магазина на самого себя и значения ниш вне ТЗ.
SQL CHECK находятся в миграциях: использовать `prisma migrate deploy`, а не `db push`.

## Атомарность

Изменения разрешений, товаров, настроек и кредитов используют блокировки строк
магазинов. Для нескольких магазинов блокировки берутся в одном порядке по ID.
После блокировки кликовая транзакция заново проверяет участников, согласия,
версии токена, срок, товар и бюджет. Условное списание, начисление, две проводки
(-1/+1), событие и погашение nonce совершаются вместе. Повтор не начисляет кредит.
WELCOME создаёт одну проводку +20; PROMO — одну положительную проводку с причиной.
Идемпотентность дополнительно обеспечивается уникальным ключом операции.

Снятые с выбора товары сохраняют запись, чтобы повторное добавление не обходило
модерацию. Изменения и webhooks инвалидируют версии ранее выданных токенов.

## Удаление

Uninstall немедленно отключает роли и каталог, инвалидирует токены версией настроек
и удаляет сессии. Старый webhook не отключает более новую установку.
Shop/redact удаляет профиль, разрешения, товары, счёт, собственные проводки,
токены и связанные данные; операции без проводок удаляются. В событиях другой
стороны идентификатор удалённого участника обнуляется, её история сохраняется.
Для запрета повторного бонуса остаётся только BonusReceipt. Основание хранения
этого минимального признака согласуется отдельно до публикации.
Данные покупателей не собираются; customer compliance-запросы подтверждаются
без сохранения их payload.
